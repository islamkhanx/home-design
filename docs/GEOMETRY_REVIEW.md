# Автоматическая проверка геометрии и расстановки

Находки покомнатного обзора превращены в повторяемые проверки канонической
сцены. Они читают текущую модель, не запускают генератор интерьера и не исправляют
входные данные перед проверкой. Blender, браузер и изображения не нужны.

```sh
npm run review:geometry
npm run test:review
npm test
npm run build
```

Первая команда проверяет фактическую квартиру. Вторая запускает общие правила,
намеренно сломанные примеры и прежние подробные регрессии. Полный `npm test`
включает новые тесты автоматически.

## Алгоритмы и решения квартиры разделены

`src/review/` содержит функции геометрии, расстановки, креплений, движения и
навигации. В этих алгоритмах нет названий комнат или ID мебели этой квартиры.
`home-profile.ts` отдельно задаёт минимальные сохраняемые зазоры, проверяемые
пары, выбранные петли, отодвигание стульев и точки использования.

Порог зазора в профиле — проектное намерение для этой расстановки, а не норма
строительства. Например, профиль сохраняет 1000 мм между кроватью и шкафом.
Высота потолка не зашита в проверку: она берётся из реального меша над шкафом.
Точки подхода к мебели привязаны к её локальным координатам и следуют за
перемещением и поворотом предмета. Камеры комнат и начало маршрута задаются
отдельно. Проверка не переносит занятую точку в ближайшее свободное место.

Для нового намерения добавьте отношение в профиль, а не исключение из алгоритма:

```ts
{ id: 'bed-access', kind: 'gap', left: 'bed', right: 'wardrobe',
  axis: 'z', minMm: 1000 }
```

Такой зазор направлен от максимальной границы `left` к минимальной `right` по
мировой оси. Для произвольного поворота используйте проверку реальных деталей
или область движения; осевой зазор сам по себе не доказывает опирание или проход.
Для нового правила добавьте положительный пример и поломку, которая должна
быть найдена. Отсутствие объекта профиля, неизвестный тип правила и неверные
допуски не должны превращаться в успешную проверку.

## Отчёт и автоматизация

```sh
# Чистый JSON в stdout; npm -s убирает заголовок npm.
npm run -s review:geometry -- --json

# Сохранение локального машинного отчёта без рендеров.
npm run review:geometry -- --output exports/geometry-review/report.json

# Любое предупреждение также означает ненулевой код завершения.
npm run review:geometry -- --strict

# Другая квартира: общие правила без привязок этой расстановки.
npm run review:geometry -- --input /path/to/apartment.json --profile none
```

Отчёт содержит SHA-256 прочитанного файла, ревизию, профиль, покрытие, ID объектов
и деталей, величины зазоров, первые конфликтные положения, маршруты и ограничения.
`--profile none` явно отмечает, что проектные зазоры, движения и маршруты не
проверялись. Отчёт не записывается поверх входной модели, включая ссылки на неё.

Код завершения: `0` — ошибок не найдено, `1` — ошибки либо предупреждения в
режиме `--strict`, `2` — неверный ввод или невозможность выполнить проверку.
Статус `review-required` сохраняется при предупреждениях или незакрытых ручных
вопросах; успешный код `0` не означает, что квартиру можно отдавать в производство.

## Границы доказательства

- Для прямоугольных частей пересечение объёмов подтверждается OBB/SAT.
  Для округлых, сложных или скошенных преобразованием мешей пересечение
  ограничивающих объёмов — только кандидат на просмотр, поэтому это warning.
- Касание и погрешность до 0,1 мм не считаются объёмным пересечением.
  Отдельные предметные тесты могут требовать более строгий допуск.
- Все стены проверяются между собой, но мебель проверяется по объявленным
  отношениям и движениям. Намеренные вложения техники, мойки и столешницы
  не дают оснований объявлять все пары объектов непересекающимися.
- Потолок проверяется в пяти точках; это не доказательство контакта всей площади.
  Открывания дискретные: шаг 2°, выдвижения — 25 мм. Очень узкий конфликт между
  отсчётами может потребовать меньшего шага или отдельной проверки поверхности.
- Навигация использует зазор камеры 140 мм и сетку 80 мм. Сегменты дополнительно
  проверяются против непрерывных габаритов препятствий. Найденный маршрут —
  маршрут камеры, а не подтверждение удобства человека. Ненайденный маршрут
  отмечается предупреждением с разрешением сетки; занятый старт/финиш — ошибкой.
- Закрытый фасад или телевизор перед розеткой означает необходимость проверить
  доступ. Задник шкафа или отделка, перекрывающая контакты, — ошибка геометрии.
  Лучи не моделируют руку, штекер, шланги и обслуживание.
- Выбранные кухонные петли и условные фасады приборов проверяются по профилю.
  Паспортная кинематика оборудования и одновременное открывание всех дверей
  этим не подтверждаются. Колонна стиральной машины остаётся отдельным вопросом.

Изменения этого этапа относятся к проверкам и документации. Модель квартиры,
её отделка и размещение мебели не изменены; новые изображения не создавались.
