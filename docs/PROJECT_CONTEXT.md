мебель, декор, электрика и потолки строятся из канонической модели. Для инженерии,

не выдаются за выполненную проверку или сопровождение. Все помещения включены

санузлом; его подтверждённые исключения сохранены. Это предварительный комплект; обмеры,
артикулы, инженерные решения и цены не утверждены.
`npm run documents:pdf` использует Swift/AppKit на macOS с совместимым SDK;
универсальный путь — печать автономного HTML в PDF через браузер.

## Цель и порядок работы

Квартира для одного человека. Нужны согласованный дизайн, схемы, спецификации и смета, затем комплект рабочих листов. Ориентир состава листов от пользователя: https://земстандарт.рф/sheets (состав сверён 21.11.2026; соответствие отражено в реестре генератора). Сначала сравниваем количество и расположение элементов и зоны материалов; затем уточняем размеры, изделия и стоимость.

Каждый выбор показывать визуально на той же планировке. Сравнивать варианты при одинаковых камере и свете. Для точных схем использовать код и геометрию, не генерацию картинок. Пояснять стойкость к повреждениям/воде, возможность самостоятельной сборки, качество внешнего вида и сложности монтажа. Принимать решение только после ответа пользователя; рекомендации не считать утверждёнными.

## Технический контекст

Vue 3 + Vite + TypeScript + Three.js / TresJS / cientos. Приложение read-only: виды, камера, размеры, сценарии света. Редактор, иерархия объектов и кнопки Blender удалены по запросу пользователя.

Геометрия задаётся в миллиметрах, мир Three.js — в метрах. FAST и PERFECT используют одну экспортированную геометрию. PERFECT: Three.js GLTFExporter → GLB + metadata → Blender bpy / Cycles; архитектуру в Blender заново не строить. Никакой облачной рендер-службы.

Важно различать три слоя:

1. `docs/bathroom-spec.json` — реестр решений, не полный геометрический JSON.
2. `src/data/apartment.json` — исходная геометрия интерактивного демонстратора. Ревизия 3 синхронизирована по композиции A3, светлому камню M1, форматам T1 и оттенку Д2. Ночной свет удалён. У1 остаётся визуальным направлением без конструктивной деталировки; полотенцесушитель не размещён до выбора места и модели. Габариты условные, свет G1/G2 — предложение.
3. `design/bathroom-v01/*.json` — параметрические исследования композиций; `scripts/export-layout-studies.mjs` создаёт общую для Three.js и Blender геометрию вариантов. Последняя сравнительная сцена дерева — `bathroom-a3-wood.json` (выбран D2). Её размеры всё ещё условные; детальная конструкция запила У1 в упрощённой модели не подтверждена.

Текущий выбранный вариант использует один канонический источник `src/data/apartment.json` для обоих рендереров. Не создавать независимо расходящиеся модели FAST и Blender.

Blender установлен на машине в `/Applications/Blender.app/Contents/MacOS/Blender`; на других машинах путь задаётся `BLENDER_PATH`. Swift-компоновщики используют AppKit и работают на macOS. PNG и SVG уже сохранены и открываются на других платформах без запуска Swift.

## Что делать дальше

1. Показать варианты формы и размещения электрического полотенцесушителя на выбранной планировке, проверить проходы и открывание мебели.
2. После выбора дополнить Э1 точкой питания, управлением и привязками. Уточнить необходимость бойлера и защиты от протечек.
3. Выбрать конструкцию фасадов Ф1/Ф2/Ф3, фурнитуру, ручки и доступ к обслуживанию.
4. Получить реальные обмеры и инженерные данные; проверить мебель, ванну, инсталляцию, люки, вентиляцию, электрозоны.
5. Подобрать конкретные артикулы и составить смету с количеством, запасом, работой, источником цен и датой.
6. Детализировать У1 и полотенцесушитель в канонической модели после выбора; затем расширять проект на остальные помещения.

Не утверждены окончательная смета, список закупки, рабочая электрика, трассы сантехники, монтажная раскладка плитки и общий метраж стен.

## Исправление после сверки источников · ревизия 5

Ревизия 4 отозвана: автоматически придуманная архитектура не соответствует исходной схеме. Подробности и ограничения — [SOURCE_GEOMETRY_AUDIT.md](SOURCE_GEOMETRY_AUDIT.md). ## Видеотур · 15 ноября 2026

В браузерном виде «Внутри» теперь можно ходить: клик по сцене даёт фокус, WASD перемещают по горизонтали, Shift увеличивает скорость, перетаскивание мышью и стрелки поворачивают взгляд, колесо меняет фокусное расстояние. Стены и мебель блокируют движение; при потере фокуса клавиши сбрасываются. Внутренние двери открыты в отдельной презентационной копии, входная дверь остаётся закрытой. Проверка препятствий и дверные положения общие с видеотуром. После выхода из режима исходные положения дверей восстанавливаются.

По новому запросу добавлены локальные Blender-контролы только на отдельной вкладке «Видеотур». Текущая логика — непрерывная прогулка внутри, а не нарезка изолированных комнат. Длительность по умолчанию 60 с; прогресс, ETA, пауза/продолжение и явный GPU/CPU выбор сохранены. Межкомнатные двери открыты в отдельной презентационной копии; исходные стены, мебель и сохранённые положения дверей не меняются. Внутренние виды всех комнат сохраняют всю окружающую геометрию, чтобы стены за дверями не исчезали. Камера санузла перенесена из хозяйственного шкафа в свободную зону; генератор использует ту же исправленную позицию. Маршрут привязан к текущему эскизу и пересчитывается с проверкой препятствий; при непроходимости запуск должен завершаться понятной ошибкой, без пролёта сквозь стену.
